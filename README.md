# 本地视频工作室 · Local Video Studio

> 一台 MacBook Air（Apple M5 / 24GB）+ 一套开源工具，搭出来的 AI 视频生产线：
> 剧本 → 静帧 → 视频生成 → 配音 → 对口型 → 剪辑合成 → 转写质检，九个站，逐站实测验活。
>
> An AI video production line that runs **locally** on a single MacBook Air — nine stations, every one of them verified with live probes, not brochure claims.

## 为什么要本地搭

云端产线有三个老问题：要在网页上一页页点、按积分计费且余额不可控、平台规则一变全线停摆。本地工作室的想法很简单：能本地跑的环节全部本地跑（生成、配音、转写、合成），云只留给本地确实做不到的两件事（锁脸静帧、生产级对口型），而且云端也要走 API 程序化调用，不点网页。

## 踩坑实录（这一节是这个仓库最值钱的部分）

1. **喂给生成 API 的图片链接，必须是对方服务器真能下载的地址。** 某些文件分享直链对外部抓取直接回 403，任务在生成端内部跑了两分半才报一个含糊的 InternalServiceFailure。修法：喂之前先用最朴素的 curl 验一遍（200 + 图片类型 + 字节数对得上），别信「链接能打开」——浏览器能打开不等于服务器能抓。
2. **API 地址只认官方文档，别信第三方总结。** Vidu 的官方 API 在 `api.vidu.cn`、路径前缀 `/ent/v2`；而流传很广的 CLI 工具用的是另一套面（`service.vidu.cn`）。按第三方资料接线，鉴权会在错误的网关上撞一晚上 401/403，key 和余额全是好的也通不了。
3. **模型许可是按引擎逐个算的。** 本地 TTS 默认引擎是 CC-BY-NC（非商用）——个人体验没问题，商用内容必须换引擎并逐一核许可。应用开源 ≠ 模型权重开源，更 ≠ 可商用。
4. **对口型管线大多是 CUDA-only。** 在 Apple Silicon 上，某主流本地工具的对口型页面直接写明需要 NVIDIA 显卡、连安装入口都不给。先查硬件门槛再下几十 GB 的模型包——我们下了 31GB 才发现无处落地。
5. **「能不能看见 GUI 窗口」是按应用逐个测的事，别下通论。** 同一个截图通道：某剪辑软件的窗口三种截法全灭（空白/挂死），而 Electron 应用一次成功、清晰可读。先实测再下结论，包括对自己的工具下结论。
6. **验活纪律：状态只来自实测，交叉验证优先。** 每一站的「活」都要有当日探活证据；最硬的一次验证是让转写站把配音站生成的语音转回文字，与原文逐字对齐——两个站一次互相验了。
